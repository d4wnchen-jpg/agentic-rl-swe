# 可行性 memo（v0.1，2026-11-03 晚）

> 目标：回答“pivot 机制在 code agent 场景下多大程度成立”，据此决定论文选题方向（11-10 go/no-go）。
> 数据：flask-5063 × 10、flask-4045 × 5；DeepSeek-chat + mini-swe-agent；官方 eval 语义；原始数据在 `results/`。

## 1. 方法（一句话）

对每条 agent 轨迹：逐轮重放命令 → 每轮用官方 pytest 口径判分 → 得到测试状态轨迹 → 对状态变化轮做**反事实重放**（跳过该轮）→ 判定该编辑是 **有害 / 有益 / 不可归因**；对「回归→恢复」配对再做 skip-recovery 验证。
保真度用「重放终态 vs agent 提交 patch」逐文件比对。

## 2. 结果

### Q1 保真度（重放可不可信）

| 项 | 结果 |
|---|---|
| 代码文件与提交 patch 一致 | **5/5**（唯一差异是 agent 自产的 `patch.txt`） |
| 重放命令失败 | 0–1 条/轨迹，不影响终态 |

→ **通过**。

### Q2 标签产出率（能不能抽到可验证 pivot）

| 实例 | n | 失败 | 有害标签 | 可恢复配对 | 有益标签 | G1-any |
|---|---|---|---|---|---|---|
| flask-5063 | 10 | 7 | 2（2/2 验证） | 7 条轨迹 / 8 对（跳过恢复变差 7/8） | — | 9/10 |
| flask-4045 | 5 | 5 | 0 | 0 | **5/5 验证** | 5/5 |
| 待补 | 第三实例 | | | | | |

- 失败模式**实例依赖**：5063 以“改坏/可恢复”为主；4045 全是“只修一半”（omission），靠 beneficial 标签覆盖。

### Q3 因果可验证性

- harmful：2/2 致命回归验证成功（1 条 cf、1 条文件级兜底）；
- beneficial：5/5 cf 有效（delta=+1）；
- 恢复配对：8 对，原始因果 7/8（严格口径受有效性判据限制，已改为相对基线比较）。

### Q4 相对教师增量（公平对照）

| 组 | 轮次 exact | ±1 | 符号说反 | 无编辑仍指认 |
|---|---|---|---|---|
| 教师原版 | 64%（9/14） | 79% | 5/9 | 1/1 |
| 教师 + 逐轮状态 | **71%（10/14）** | 71% | **5/10** | 1/1 |
| 随机基线 | 4.9% | — | — | — |

**教师能定位轮次（远高于随机），但给不给测试状态都分不清“有害/有益”，也从不承认“没有关键步”。**

## 3. 结论（对选题）

1. **能成立的部分**：执行验证可以产出 **signed、可因果检验**的 turn 级标签，覆盖两类失败模式（regression 型 / omission 型）；
2. **不成立/有限的部分**：标签产出率依赖实例（4045 无 harmful、5063 无 beneficial 主导）；样本小（15 条 / 2 实例）；“无可归因编辑”是否定性命中；
3. **相对教师的增量明确**：符号 + 承认“无 pivot”，而不是轮次定位（教师已能做）。

**建议选题**：
> **A（主）+ B（分析）**：*Signed, execution-verified credit labels for code agents* —— 方法上给 signed 标签，分析上回答“什么实例/轨迹能产出可验证 pivot（产出率预测）”。

## 5. 局限（写进论文）

- 单一模型（DeepSeek）+ 单一 scaffold（mini-swe-agent bash）；
- 教师只看截断轨迹（与给状态的版本 prompt 略有差异）；
- “beneficial”= 对失败数有正贡献，不等于“正确策略”（可能只是修好一个测试）；
- 无编辑可归因 = “没有单个编辑对最终失败有因果贡献”，不是“没有错误决策”。
