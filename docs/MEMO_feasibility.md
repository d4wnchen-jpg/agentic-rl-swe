# 可行性 memo（v1.0，2026-11-03 晚）

> 目标：回答「pivot 机制在 code agent 场景下多大程度成立」，据此决定论文选题方向（11-10 go/no-go）。
> 数据：3 个实例 / 20 条轨迹（flask 系 ×2 + requests ×1）；DeepSeek-chat + mini-swe-agent；官方 eval 语义；原始数据在 `results/`。
> **验证范围**：这是小规模可行性验证（20 条），不是论文的实验数据；论文会在更大规模、多 repo、多模型上做。

## 1. 方法（一句话）

对每条 agent 轨迹：逐轮重放命令 → 每轮按官方 pytest 口径判分（整文件 + 还原 test 文件）→ 测试状态轨迹 → 对状态变化轮做**反事实重放**（跳过该轮）→ 判定该编辑是 **harmful / beneficial / 不可归因**；对「回归→恢复」配对再做 skip-recovery 验证。
保真度：重放终态 vs agent 提交 patch 逐文件比对。

## 2. 结果

### Q1 保真度

| 项 | 结果 |
|---|---|
| 代码与提交 patch 一致 | **5/5**（唯一差异：agent 自产 `patch.txt`） |
| 重放命令失败 | 0–1 条/轨迹，不影响终态 |

→ **通过**。

### Q2 标签产出率（三实例）

| instance | n | failed | harmful | beneficial | recovery pairs | cf-verified any |
|---|---|---|---|---|---|---|
| flask-5063 | 10 | 7 | 2 | 0 | 8（7 条轨迹） | 2/10 |
| flask-4045 | 5 | 5 | 0 | 5 | 0 | 5/5 |
| requests-3362 | 5 | 0 | 0 | 5 | 0 | 5/5 |
| **合计** | **20** | **12** | **2** | **10** | **8** | **12/20 = 60%** |

- **标签类型由失败模式决定**：flask-5063 以「改坏再修 / 改坏不修」为主（recovery pairs / harmful）；flask-4045 与 requests-3362 以「只修一半」或「修好」为主（beneficial）。
- 单实例内产出率：5063 的 recovery 覆盖 7/10；4045、3362 的 cf-verified 覆盖 5/5。

### Q3 因果可验证性

- harmful：2/2 致命回归验证成功（1 cf + 1 文件级兜底）；
- beneficial：10 个（7 cf + 3 文件级兜底）；
- recovery 配对：8 对，原始因果（跳过恢复→终态变差）7/8。

### Q4 相对教师（20 条，修正实验）

> 说明：旧版 Q4（"教师+状态 exact 79%、符号说反 10/15"）是**提问方式造成的假象**，已被本实验推翻，旧表作废。

**设计**：给教师逐轮 `n_fail`，用三种中性提问，与我们的可执行反事实标签比较。

| 任务 | 问题 | 结果 | 含义 |
|---|---|---|---|
| A 方向 | 哪些步变坏/变好？ | **31/31 = 100%** | 读数字即可，不需要模型 |
| B 因果 | 跳过哪一步会改变最终结果？ | **1/19 = 5%** | 几乎全答"没有" |
| C 存在性 | 是否存在可归因的单轮？ | 我们有 19 条，教师答"有" **0/19** | 系统性否认 |

**对照旧实验**：旧 prompt（"哪一步是关键错误"）下，教师在无错误轨迹上仍指认（13/15 = 87%），
即**同一教师：换问法 → 从过度归因翻转到全部否认**。

**论文口径**：
> 教师能读状态方向（100%，但这是免费信息）；它不能做反事实因果推断（5%，且几乎总答"没有"）；
> prompt 措辞可让判断在“过度归因/全部否认”之间翻转。**因果标签只能来自执行验证。**

## 3. 结论（对选题）

1. **成立**：执行验证能产出 **signed（harmful/beneficial）、可因果检验**的 turn 级标签；覆盖“改坏”和“只修一半/修好”两类轨迹；跨 3 个 repo 可复现。
2. **不成立/有限**：产出率**取决于实例的失败模式**；n 小（20 条）；「无错误可归因」是否定性命中（依赖我们的因果定义）。
3. **相对教师的增量明确**：**符号 + “无 mistake”判定**，而非轮次定位（教师已有 80%）。

**建议选题**：
> **A（主）+ B（分析）**：*Signed, execution-verified credit labels for code agents* ——
> 方法上给 signed 标签与“无错误”判定；分析上回答“什么实例/轨迹能产出可验证 pivot（失败模式 → 标签类型的映射）”。

## 5. 局限

- 单一模型（DeepSeek）+ 单一 scaffold（mini-swe-agent bash）；
- 教师 prompt/截断在两个版本间不完全一致；
- beneficial = 对“失败测试数”有正贡献，≠“正确策略”（可能只是修好一个测试）；
- 「无可归因错误」= 没有**单个编辑**对最终失败有因果贡献，不是“没有错误决策”。

# 追加：demo 阶段结果（v1.1，2026-11-06 晚）

> 目的：把「标签在失败后有没有用」从诊断推进到**受控下游实验**；同时定 demo 口径。
> 数据：flask-5063（F2P=2/P2P=54）新生成 50 条轨迹（失败 33 条）→ 选 9 条含已验证有害步的失败轨迹；每条件 8 步 continuation agent；官方 eval 语义。原始数据 `results/repair_d1a*/`。

## 1. 实验设计

对每条失败轨迹重建最终状态，四种干预（其余相同）：continue（不动）/ revert_random / revert_teacher / revert_ours（撤销我们验证过的有害轮），之后同一个 continuation agent 继续 8 步，再评测。

## 2. 结果

| 条件 | 干预后 n_fail 均值 | 恢复到基线 2 | 最终 n_fail 均值 | 最终 f2p_pass | resolve |
|---|---|---|---|---|---|
| continue | 15.3 | 0/9 | 9.3 | 1 | 0/9 |
| revert_random | 15.3 | 0/9 | 15.3 | 1 | 0/9 |
| revert_teacher | 14.7 | 3/9 | 14.9 | 1 | 0/9 |
| **revert_ours** | **2.0** | **9/9** | **2.0** | 0 | 0/9 |

配对最终 n_fail：ours−random −13.3 [−30.6,−1.4]；ours−teacher −12.9 [−30.2,−0.8]；ours−continue −7.3 [−19.2,−0.8]（bootstrap，n=9）。

精确回退补充（只反转该轮 diff、3way）：9/9 仍恢复基线 2，结果与整文件回退一致（3/9 走精确路径）。

## 3. 结论

1. **成立**：执行验证标签能因果定位自伤编辑——撤销标注轮后 9/9 恢复基线；random 0/9、teacher 3/9；对照与 CI 显著。这是 demo 的主效果证据。
2. **不成立**：**resolve 无提升**（0/9 所有条件）。撤销后只剩原始 F2P（原始 agent 30–51 轮未解决），8 步续跑 agent 修不出来。「清除自伤」≠「修好任务」。
3. **已知失效模式**：回滚**非交换性**——后续轮代码建立在有害轮之上，撤销后状态 ≠「从未执行该轮」；case 15 因此从 1 个失败退回 2 个。粒度（整文件 vs 精确 diff）不是瓶颈。

## 4. demo 口径（对外）

- 主 claim：*PivotInspector 用测试执行验证出 signed 因果标签；据此可精确定位并清除 agent 的自伤编辑*；
- 对照：教师能定位（79%）但 10/15 符号说反；中性问法 100% 读方向、5% 答因果；
- limitation 如实写：resolve 无提升（续跑 agent 能力 + 回滚非交换性）、9 条轨迹/1 实例。

## 5. 对 11-10 go/no-go 的影响

- 选题 A（signed execution-verified labels）+ B（失败模式→标签类型映射）仍然成立；
- 新增定位：论文的「训练信号」主张需要跨过 resolve，需要在更大模型/更多步预算下验证；
- demo 可在 11-10 前交付诊断 + 清理效应；训练实验仍需 GPU（4×A100，2–3 周）。
